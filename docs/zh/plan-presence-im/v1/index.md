## 0. 参考对象：学什么 / 不学什么

DeepSeek Harness 插件 `dsh-im-style-fatfish` 的核心体验：

| 维度 | 大肥鱼做法 | 阿盆要不要 |
|---|---|---|
| 头像挂在助手消息旁（宽屏在对话栏**外侧**空白，正文不让位） | ✅ | **学** |
| 名字在正文上方，IM 气泡外感觉 | ✅ | **学** |
| 运行中固定「思考」脸 | ✅ `think` | **学** → 复用现有 `thinking` |
| 轮次结束从表情库挑一张 | ✅ 小模型 12 选 1 | **学机制，缩库** → 对齐现有 `FaceState`（7 态），默认规则映射，可选 LLM |
| 12 张二创表情包 / 鲸鱼娘人设 / 桌宠 iframe | 大肥鱼社区 IP | **不学**（版权与品牌冲突） |
| 把默认皮肤换成 DeepSeek logo 小鲸 | 本仓已有 `deepseek` skin | **保留为可选皮肤**，默认建议改回「盆栽 · 经典」或新「盆」表情包 |

产品立场：阿盆仍是窗台盆栽 companion（`persona.json` 权威），视觉与人格不漂移成「另一条大肥鱼」。

## 1. 现状问题

```
现在（有消息时）：

┌──────────────────────────────────────┐
│ ≡                         ⚙ 阿盆 ◎  │  ← 顶栏有脸
├──────────────────────────────────────┤
│                                      │
│              [用户气泡]              │
│  [助手气泡 · 无头像]                 │  ← 对话里「人」消失
│              [用户气泡]              │
│  [助手气泡]                          │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 输入…                        │    │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘

空态才有大脸；有会话后形象退居顶栏 28px，消息流纯文本，像工具不像陪伴。
```

| 缺口 | 说明 |
|---|---|
| 消息行无 presence | `MessageBubble` 只有 bubble，无 avatar / 名 |
| 表情与回合脱节 | `FaceState` 驱动顶栏/空态；流式时未必稳定切到 `thinking` 并锁在当轮气泡上 |
| 默认皮是小鲸 logo | `DEFAULT_SKIN = "deepseek"`，品牌锚点偏外借，不是「阿盆」 |
| 自定义槽齐备但缺「回合表情」叙事 | 7 槽已与 `FaceState` 对齐，缺「每轮结算一张」的产品层 |

## 2. 目标形态（产品）

1. **有消息时也能感到「对面有人」**：每条助手回合左侧挂圆形头像；用户侧不挂（或极简，本期不做）。
2. **运行中 → 思考脸；结束后 → 本轮表情**：表情贴在**该轮助手行**，历史行保留结算结果（或回退 calm），不整页闪顶栏。
3. **宽屏 IM 外挂 / 窄屏贴身**：正文列宽尽量不被头像挤窄。
4. **空态大脸 + 顶栏小脸保留**：叠在 v2/v3 之上，不回退成仪表盘大立绘。
5. **默认视觉回到「盆」**：内置表情包以盆栽图形语汇为主；DeepSeek 小鲸降为可选皮肤。

非目标（v1）：

- 不做网页桌宠 iframe、不做斗图表情包发送、不做鲸鱼娘人设/技能注入。
- 不做用户侧头像、不做点击头像放大灯箱（可 P1）。
- 不强制每轮调云端分类模型；规则映射为默认，LLM 分类为可选增强且须用户 opt-in / 云端模式。

## 3. Wireframes

### 3.1 宽屏（≥ 约 720 逻辑宽，托盘展开或独立窗）

```
┌─ ChatChrome ─────────────────────────────────────────┐
│  ≡                                    ⚙  阿盆 ·平静 ◎│
└──────────────────────────────────────────────────────┘
┌─ messages（对话栏）─ gutter ←avatar 在栏外 ───────────┐
│                                                      │
│                              ┌──────────────┐        │
│                              │ 帮我看下这段 │ user   │
│                              └──────────────┘        │
│                                                      │
│  ╭──╮  阿盆                                          │
│  │🪴│  ┌─────────────────────────────┐               │
│  │思考│ │ 先说你的判断？我再补…        │  ← 流式中    │
│  ╰──╯  │ ▍                           │     avatar=thinking
│   64px └─────────────────────────────┘               │
│                                                      │
│  ╭──╮  阿盆                                          │
│  │🪴│  ┌─────────────────────────────┐               │
│  │平静│ │ 这段可以，但第二句证据不够。 │  ← 已结算    │
│  ╰──╯  └─────────────────────────────┘     avatar=calm/proud/…
│                                                      │
│         ※ 头像在「对话栏左缘之外」；正文左缘与用户气泡│
│           对称对齐，不因头像让位。                     │
└──────────────────────────────────────────────────────┘
┌─ Composer（浮起）────────────────────────────────────┐
│  [本地·模型]  说点什么…                    [发送]    │
└──────────────────────────────────────────────────────┘
```

布局要点：

- 消息区左 padding 预留 ≈ 64 + 12 gutters；头像 `position` 在助手行上，水平落在预留带。
- 名字「阿盆」为 11–12px muted，在 bubble **上方**（非 bubble 内）。
- 助手 bubble 仍用现有 `.bubble.bot` 样式；不改为卡片堆。

### 3.5 单行助手消息结构（组件树）

```
AssistantTurnRow
├── FaceAvatar (size=msg | msg-sm)     ← 本轮 locked FaceState
├── TurnMeta
│   └── name: "阿盆"
└── TurnBody
    ├── MessageBubble (bot | typing | …)
    ├── turn-failure? 
    └── MessageActions
```

Typing 三点可并入「thinking 头像 + 空/弱 bubble」，避免头像与三点双重噪音——推荐：**有头像时 typing 气泡可省略三点或极弱化**。

## 4. 表情状态机（回合级）

### 4.1 与现有 FaceState 对齐（不扩 12 套二创）

| 阶段 | 头像 | 来源 |
|---|---|---|
| 用户已发送、助手未结算 | `thinking` | 前端 `chatting` / streaming 布尔，零模型 |
| 流式结束且成功 | 结算态 ∈ FaceState | 见 4.2 |
| 失败 / 取消 | `displeased` 或 `sleepy` | 规则；取消偏 `sleepy` |
| 历史无缓存 | `calm` | 与大肥鱼「无缓存 → rice」同构 |
| 顶栏 / 空态 | 仍跟全局 face 推导 | 不强制等于最后一轮气泡脸 |

### 4.2 结算策略（推荐默认：**规则优先**）

避免本地管线挂工具、也避免默默烧云端：

1. **规则映射（MUST 默认）**  
   - 主动搭话 `proactive` → `greeted`  
   - 短回复且带反对/边界语气（已有 disagreement 信号可复用则用）→ `focused` / `displeased`  
   - 成长/交付类 announcement → `proud`  
   - 安静时段 → `sleepy` 权重升高  
   - 否则 → `calm`
2. **可选 LLM 分类（SHOULD，仅云端 + 用户开启）**  
   - 输入：本轮正文截断 + 成败/主动等程序事实（同大肥鱼：看事实不看关键词表）  
   - 输出：7 个 id 之一；超时 ≤2.5s → `calm`；**不阻塞**消息展示  
   - 本地模式：**不调**分类模型，诚实走规则

### 4.3 持久化

- 每条助手消息可选字段 `faceState?: FaceState`（chatStore + 历史回放映射）。  
- DB：若对话行表无列，v1 可用 session 侧 JSON 旁路或仅内存（刷新回退 calm）；**推荐**最小列/元数据，避免「永远只有当前轮有表情」。

## 5. 视觉规格

| 槽位 | 尺寸 | 形状 | 动效 |
|---|---|---|---|
| 消息·外挂 | **56–64px** | 正圆 + 1px `--line` | 结算切换一次 crossfade ≤180ms；无光晕位移 |
| 消息·贴身 | **40–44px** | 同上 | 同上 |
| 顶栏 | **28px**（v3 已定） | 正圆 | poke 保留 |
| 空态 / 设置预览 | **108 / lg** | 现有 | 可保留轻呼吸（仅 lg） |

素材：

- **盆栽经典**：继续 `BonsaiFace` SVG，按 `FaceState` + frame 两帧。  
- **自定义皮肤**：已有 7 槽，与回合表情一一对应。  
- **小鲸**：静态图无状态差 → 回合切换时仅做轻微 scale/opacity，或提示「该皮肤无分态」。

色与品牌：沿用现有绿强调（`--accent`），避免紫渐变 / 奶油衬线套装；头像区不做霓虹光晕。

## 6. 实现切片（建议）

| 切片 | 内容 | 验收 |
|---|---|---|
| **M1 布局** | `AssistantTurnRow` + 宽/窄两种挂法；名字行；不改气泡语义 | 宽屏正文左缘与改前对齐；窄屏不裁切 |
| **M2 回合锁脸** | streaming → thinking；结束写 `faceState`；历史渲染 | 单测：streaming 中强制 thinking |
| **M3 规则结算** | 4.2 规则；失败/取消分支 | 单测表驱动 |
| **M4 默认皮** | `DEFAULT_SKIN` → `bonsai`；设置文案「回合表情」 | 空态/消息默认为盆栽 |
| **M5（可选）** | 云端 LLM 分类 + 设置开关 | 关时零请求；超时回退 calm |

质量门：`cd frontend && npx tsc --noEmit`；相关 `npm run test` / lint；不改 Rust 则免 `pnpm check`。若加 DB 列则走 Rust 迁移 + `pnpm check`。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 窄托盘被头像挤爆 | 贴身 44px + 断点；可设置「消息头像：开/关」 |
| 与顶栏脸双重存在感 | 顶栏保持状态摘要；消息脸=该轮表演，允许短暂不一致 |
| 被认成抄大肥鱼 | 只用交互语法；素材与人设坚持阿盆/盆栽 |
| 每轮 LLM 分类费电费钱 | v1 不做；若做必须云端 opt-in |
