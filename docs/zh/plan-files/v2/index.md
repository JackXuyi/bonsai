# 方案：文件工具增加复制与移动（plan-files v2）

> **状态**：已实施（2026-11-25）  
> **承接**：[plan-files.md](../../plan-files.md)（P3-2 T0–T4；原「永远不做移动」裁决在本版对 **文件** 复制/移动开例外）  
> **一句话**：在授权目录内增加 `fs_copy` / `fs_move`（Ask、不覆盖、仅文件）；**删除仍不做**。

---

## 1. 为何改口

v1 把移动/改名与删除绑在一起拒绝，是为挡住不可逆破坏。复制与「同授权集合内的移动/改名」失败模式更轻（目标不覆盖、可审批预览路径），且用户明确需要「整理到另一处 / 改个名」。删除仍不实现。

## 2. 工具表（相对 v1 增量）

| 工具名 | access | 行为 |
| --- | --- | --- |
| `fs_copy` | **Ask** | `from` → `to`；双路径均过 `resolve_in_roots`；源须为已存在**文件**；目标不得已存在；父目录须存在；≤32MB |
| `fs_move` | **Ask** | 同上；优先 `rename`；跨卷（EXDEV）回退 copy + 删源；删源失败则回滚目标副本 |
| ~~`fs_delete`~~ | — | **仍不存在** |

其余 `fs_search` / `fs_list` / `fs_read` / `fs_write` 不变。权威实现：`src-tauri/src/filetools.rs`。

## 3. 不变量（继承 v1 §3.2 + 增量）

1. 源、目标都必须在用户授权 roots 内（可跨不同 root，不可逃逸）。
2. 不覆盖：目标 `exists` → `fs_exists`。
3. 不处理目录（不递归）：源为目录 → `fs_is_dir`。
4. 不代建嵌套目录。
5. AskFirstGate 强制弹卡（与 `fs_write` 同档）。
6. 审计只记路径与动作，不记文件正文。

## 4. 非目标（本期仍不做）

- 删除 / 清空目录 / chmod
- 目录树复制或移动
- 覆盖已有目标、追加写入
- 本地模式挂载文件工具（仍仅云端 tool loop）

## 5. 验收要点

- [ ] 设置页内置工具清单出现 `fs_copy` / `fs_move`，档位为「先问」
- [ ] 同 root 内复制成功；再次同目标 → `fs_exists`
- [ ] 移动后源消失、目标可读
- [ ] 源为目录 / 目标越界 → 显式错误
- [ ] 拒绝审批后不落盘
