## 一、背景与目标

### 1.1 背景

通用 Agent 赛道在 2025–2026 年完成了一次范式转移：从「聊天框问答器」转向「在你电脑/账户里干活的执行者」。行业分化为两条主线（来源：2026-11-19 联网调研，多源交叉）：

- **桌面型 Agent（数字员工）**：一次任务、分钟到小时级，在本机或云 VM 执行，代表产品如 Claude Cowork、Kimi Work、Codex App；
- **个人助理型 Agent（Personal Agent）**：持续数天到数月常驻后台，替用户「惦记」生活事务，代表如 Gemini Spark、Alexa+。

 bonsai 的定位（桌面常驻、有脾气、会成长、先干活）天然靠近第二类，但有两个硬约束：**本地 LLM（默认 qwen3.5:2b，2B 级模型）** 与 **隐私边界（原文不出机器）**。这决定了不能照抄云端大模型的 Agent 能力清单，必须按「2B 模型 + 本机执行 + 养成人格」三个过滤器做取舍。

### 1.2 目标

- 摸清通用 Agent 能力全景，形成 8 类能力图谱；
- 逐项对照 bonsai 现状做差距分析，输出「采纳 / 改造 / 缓做 / 不做」四档结论；
- 产出 P2 收尾 → P6 的分期 roadmap，每项带验收标准与依赖；
- 保持 bonsai 独有定位（成长线、人格、反谄媚、隐私），不做「又一个通用助手」。

### 1.3 成功指标（口径）

| 指标 | 口径 | 目标 |
|---|---|---|
| 能力覆盖数 | roadmap 内「采纳+改造」档条目占通用能力清单条目比例 | ≥70%（估算） |
| 本地化率 | P3 前新增能力中，不依赖云端 API 的条目比例 | 100% |
| 危险动作审批覆盖率 | 涉及写操作/外发的工具调用中，走 Ask-first 审批的比例 | 100% |

## 二、通用 Agent 能力图谱（调研摘要）

按 2026 年主流框架与产品实践（MCP 官方文档、aiwiki.ai Agent 条目、tyk.io Agentic AI 指南、桌面 Agent 调研报告，均为 2025–2026 年发布内容，引用日期 2026-11-19）归纳为 8 类：

| # | 能力类 | 包含要素 | 行业现状 |
|---|---|---|---|
| C1 | 模型与推理 | 大/小模型路由、结构化输出、思维链开关 | 成熟；2B 本地模型是主要短板 |
| C2 | 工具调用与生态 | Function calling、MCP 客户端、Skills 技能包、A2A 协议 | MCP 已成事实标准（月 SDK 下载 97M+，来源 tyk.io） |
| C3 | 记忆与个性化 | 短期上下文、情景/语义/程序记忆、RAG/向量检索、记忆可携带 | 成熟；记忆投毒是新兴安全议题 |
| C4 | 感知与执行 | Computer Use（看屏点击）、浏览器自动化、文件操作、剪贴板 | Computer Use 成底座但长任务通过率仅约 20%（OSWorld 2.0，来源调研报告） |
| C5 | 规划与长任务 | 目标分解、ReAct 循环、常驻定时任务、失败恢复 | 云端强模型可用；本地小模型尚不可靠 |
| C6 | 通信与触达 | 邮件、IM、日历、通知多通道 | 成熟，审批机制为标配 |
| C7 | 语音与多模态 | 实时语音对话（ASR/TTS）、屏幕理解 | 成熟，端侧方案可离线 |
| C8 | 安全治理与可观测 | 权限分级、Ask-first 审批、审计轨迹、提示注入防御、tracing | 所有产品将审批列为标配；可靠性是主要矛盾 |

> 引用区分：以上为「已查证的公开资料归纳」；具体产品功能细节为「参考观点」，落地前需单独核实。

## 四、差距分析矩阵（逐能力裁决）

裁决档位：**采纳**（直接补）、**改造**（按 bonsai 约束改形后补）、**缓做**（记录触发条件，暂不排期）、**不做**（与定位冲突）。

| 编号 | 通用能力 | bonsai 现状 | 裁决 | 理由 | 落点 |
|---|---|---|---|---|---|
| G-01 | 语音输入/输出（ASR/TTS） | 无 | 采纳 | 原规划 P2-3；端侧 whisper + macOS TTS 可离线 | P2-3 |
| G-02 | 屏幕感知（截图/窗口理解） | 仅 App 名称粗标签 | 改造 | 原规划 P2-4；因 2B 模型不能做多模态理解，改为「窗口标题白名单 + 用户主动圈选」的 L2，不做截屏理解 | P2-4 |
| G-03 | 记忆导出/导入（可携带） | 无 | 采纳 | 原规划 P2-5；用户对本地数据有所有权预期，也是迁移主因 | P2-5 |
| G-04 | 邮件工具 | 无 | 改造 | 原规划 T5；只读摘要先做，发送必须 Ask-first | P3-1 |
| G-05 | 文件系统操作 | 无 → **T0–T4 已实施**（2026-11-22 代码；2026-11-24 T4 真机通过，plan-files.md §11）；**PDF 文本层可读**（2026-11-24，plan-pdf-read/v1） | 改造 | 只读搜索/摘要先行；写入仅限用户指定目录且二次确认（Ask 档复用 AskFirstGate）；delete/move/rename 连执行分支都没有；PDF 仅文本层抽取（无 OCR） | P3-2（docs/zh/plan-files.md；docs/zh/plan-pdf-read/v1） |
| G-06 | Web 检索 | 无 → **T0–T3 已落地**（2026-11-23 代码；2026-11-24 T3 真机通过） | 改造 | 本地 LLM 总结网页/搜索结果；无网时明示不可用 | P3-3（plan-web.md §11） |
| G-07 | MCP 客户端 | 无 → **已落地** | 采纳 | 行业标准工具协议；本地 stdio MCP 服务器不影响隐私定位 | P3-4（2026-11-20 实施，stdio + Streamable HTTP） |
| G-08 | 定时/常驻任务 | 仅夜间 consolidate、提醒 lane | 改造 | 把 consolidate 模式推广为通用 job 表（cron 语义），为 C5 铺路 | P3-5 |
| G-09 | 轻量任务模式（目标→步骤→执行→验证） | 无（单轮对话+规则路由） | 改造 | 2B 模型跑不稳自由 ReAct；改为「结构化任务卡」：LLM 只填字段，执行与重试由 Rust 引擎控制 | P4-1 |
| G-10 | 工具权限分级 + Ask-first 审批 | 隐性（日历只读无需审批） | 采纳 | 工具增多后必须显式化：只读/询问/禁止三档 + 审批 UI | P4-2 |
| G-11 | 审计轨迹（工具调用日志） | tool_calls 仅计数 → **最小版已扩** | 改造 | 扩为「参数摘要+结果状态+时间」审计表，UI 可查 | P4-2（最小版随 P3-4 落地；权限分级仍在 P4-2） |
| G-12 | 提示注入 / 记忆投毒防御 | 无 → **最小版已落地** | 采纳 | G-06/G-07 引入外部内容后必做；策略：外部内容打标签、永不直接入库为事实 | P4-3（skill 注入黑名单 + 工具结果只以摘要进 prompt、原文不入库不抽取，随 P3-4 落地；untrusted 标签随 P3-3） |
| G-13 | 向量检索 / RAG | 索引层已上（S0→S1→S2 FTS5）；**S3 查询侧同义簇 2026-11-24** 近义 1/12→12/12 | 缓做 | embedding 等簇外冷门改写或规模触发；trigram 已证否，现用 2-gram + unicode61 + synonym | P5 视新触发 |
| G-14 | Computer Use（截屏点击） | 无 | 缓做 | 2B 模型不可靠（行业长任务通过率仅约 20%）；触发条件：默认模型 ≥7B 多模态且实测通过率可接受 | 远期 |
| G-15 | 浏览器自动化 | 无 | 缓做 | 依赖 G-14 之外的登录态与稳定性方案；先以「打开 URL + 读页面」半自动替代 | 远期 |
| G-16 | 多 Agent 协作（A2A） | 无 | 不做 | 单盆栽定位：一个搭子，不是一群工蜂；工程上小模型多 Agent 不可靠 | 不做 |
| G-17 | 云端模型混合路由 | 显式开启可选 | 维持 | 现有决策：本地优先、云端为显式增强；不扩 | 维持 |
| G-18 | 可观测性（对话/决策 trace 导出） | 事件表隐含 | 改造 | 低成本：导出当日 decision/tool/reply 时间线供用户自查 | P4-3 |
| G-19 | 数据隔离/多用户 | 单用户 | 不做 | 桌面单机定位 | 不做 |

## 五、Roadmap 分期

### P2 收尾（原 P2 计划 + 差距分析确认项）

| 编号 | 事项 | 方案要点 | 验收标准（Given/When/Then 摘要） | 依赖 |
|---|---|---|---|---|
| P2-3 | 语音输入与播报 | 端侧 ASR（whisper.cpp 或系统能力）→ 走现有 chat_turn；TTS 用系统语音合成；逐项授权默认关闭 | Given 授权开启，When 按住快捷键说话，Then 文本进入对话且可用开关关闭；Given 未授权，Then 无任何音频采集 | sidecar 就绪 |
| P2-4 | 屏幕感知 L2（改造） | 窗口标题白名单抓取（仅用户勾选的 App）+ 用户主动「教」盆栽的名词；不截屏、不做视觉理解 | Given 用户勾选某 App，When 前台切换，Then 仅该 App 粗标签入事件；Given 未勾选，Then 事件无窗口信息 | perception.rs 扩展 |
| P2-5 | 数据可携带 | 一键导出：SQLite 全量 + persona.json + 设置 → 单文件 zip（含 schema 版本）；导入校验 schema 后合并/替换二选一 | Given 导出，When 换机导入，Then 对话/记忆/成长/边界全部恢复且人格不变；Given schema 不匹配，Then 明确报错不写入 | schema v8 稳定 |
| P2-6 | 打包发布实测 | sidecar + ollama-runtime 进 bundle；签名与公证流程 | ✅ **2026-11-24 真机通过**（P2-12）：干净机 dmg 断网可聊 | 229MB runtime 裁剪评估 |

### P3：工具与生态扩展（「能干活」主线）

| 编号 | 事项 | 方案要点 | 验收标准 | 依赖 |
|---|---|---|---|---|
| P3-1 | 邮件只读 + 摘要 | MailKit/系统框架只读；摘要走本地 LLM；发送功能仅出「草稿」不发送 | Given 授权，When 用户问「今天有什么邮件」，Then 摘要准确且原文不出机器；Given 未授权，Then Err(mail_denied)（对齐日历 TCC 教训） | 日历 TCC 验收经验 |
| P3-2 | 文件操作（分级） | T0：指定目录内搜索+读取+摘要；T1：写文件（仅用户显式给的目录+二次确认）；禁止移动/删除 | Given T0 授权目录，When 查询，Then 仅返回该目录内容；Given 删除请求，Then 永远拒绝 | P4-2 权限框架可并行设计 |
| P3-3 | Web 检索 | 系统默认浏览器打开 + 本地抓取（HTTP 客户端）→ 本地 LLM 总结；外部内容强制打 untrusted 标签 | Given 断网，When 触发搜索，Then 明示「当前离线」不虚构；Given 抓取到网页，When 总结，Then 引用含 URL 可溯源 | G-12 同期落地 |
| P3-4 | MCP 客户端（stdio + HTTP） | ✅ **已实施（2026-11-20）**：rmcp 官方 SDK 双传输（stdio 子进程 / Streamable HTTP）、schema v8 `mcp_servers`、三级渐进注入（名称→候选→详情）、`ApprovalGate`（默认 auto；ask 弹卡 30s 超时拒绝）、tool_calls 审计（脱敏参数摘要 + result_status + prompt_trace）、Skill 包提示注入同期落地 | 见 docs/zh/plan-agent-mcp-skill.md §8；真机项待验（MCP 实连 / 2B 误触发率） | P4-2 审批框架的**钩子**已先行（分级仍在 P4-2） |
| P3-5 | 常驻任务框架 | job 表（schema v9 —— v8 已被 mcp_servers 占用）：name/cron/last_run/status；把 consolidate、日报、提醒 lane 迁入统一调度 | Given 新增 job，When 到达计划时间，Then 执行且失败有重试上限（≤3）与状态记录 | 现有 scheduler.rs |
| P3-6 | 打包发布 | | | （合并入 P2-6，此处占位保持编号连续） |

### P4：从「会答」到「会办」——规划与治理

| 编号 | 事项 | 方案要点 | 验收标准 | 依赖 |
|---|---|---|---|---|
| P4-1 | 任务卡模式 | 用户说目标 → LLM 产出结构化任务卡（步骤 JSON、每步绑定工具+参数+校验）→ Rust 引擎逐步执行；LLM 不直接执行任何动作 | Given「把这两个文件合并成一份摘要发到剪贴板」，When 任务卡生成，Then 每步可预览、可取消；Given 任一步校验失败，Then 停止并报告而不是继续 | P3-2/3-4 |
| P4-2 | 权限分级 + Ask-first + 审计 | 工具三级：只读（直接）/询问（弹窗批准）/禁止；audit 表记录参数摘要+结果+时间戳；UI 审计页 | Given 写类工具，When 未批准，Then 拒绝执行且记录；Given 用户查看审计页，Then 可看到全部工具调用时间线 | P3 全部工具接入 |
| P4-3 | 外部内容安全 | untrusted 内容永不直接写事实表；入记忆必须经 consolidate 且带来源标签；注入特征（指令式文本）标记降级 | Given 网页含「请忽略之前指令」，When 进入上下文，Then 盆栽不执行该指令且事件留痕 | P3-3 |
| P4-4 | 能力线接入任务卡 | 任务卡完成质量计入能力线成长（对齐「理解准确度」哲学） | Given 任务卡全部校验通过，When 结算，Then 能力线获得当日证据 | P4-1、growth 模块 |

### P5：打磨期（触发条件驱动，不预设日期）

| 编号 | 事项 | 触发条件 |
|---|---|---|
| P5-1 | 向量检索 / 本地嵌入 | S3（2026-11-24 同义簇）后近义改写 **12/12**，原「<3/12」触发条件已不成立；改触发：facts+events 有效行 > 5k 且命中率下行、或 ≥3 次真实召回投诉、或同义簇外冷门改写集命中 <50%。基线见 `memory/eval_recall.rs` / `memory/synonym.rs` |
| P5-2 | 模型升级评估（≥7B 多模态） | 硬件基线明确 + 社区侧反馈 2B 不足以支撑 P4 任务卡质量 |
| P5-3 | Computer Use 探索 | P5-2 通过且 OSWorld 类自测通过率可接受 |
| P5-4 | 多通道触达（App 推送/邮件通知） | 用户增长后「人不在电脑前」场景占比可测 |

### 明确不做（维持并新增）

- 恋爱/虚拟伴侣、角色扮演社区、角色商店、无限对话（原红线）；
- G-16 多 Agent 集群：与「一个搭子」人格定位冲突；
- 后台静默截屏：与「原文不出机器 + 逐项授权」底线冲突；
- 任何免审批的写操作与外发动作。

| RK-02 | 工具增多后隐私边界被稀释 | 合规 | 3 | 5 | 15 高 | 权限三级硬约束 + 审计页 + 「原文不出机器」进宪法层（L1 人格不可变） |
| RK-03 | P2 收尾拖延挤压 P3 | 进度 | 3 | 3 | 9 中 | P2-6 与 P3 设计并行；P3 不依赖 P2-3/4/5 |
| RK-04 | MCP 生态工具良莠不齐（恶意 server） | 技术 | 3 | 4 | 12 中 | 默认询问档 + 来源展示 + 永不自动启用新 server |
| RK-05 | 范围蔓延：通用能力越加越多，养成系灵魂被稀释 | 需求 | 4 | 4 | 16 高 | 本文档「不做」清单为宪法；每个新能力必须能回答「这让盆栽更懂我还是更能干」 |

## 八、演进原则（评审锚点）

1. **先干活，才谈得上陪你**：每期至少有一个「用户能交付结果」的能力（P3 干活、P4 会办）；
2. **能力长在成长线上**：新能力尽量接入能力线证据（P4-4 为范式）；
3. **危险动作永远是 Ask-first**：审批不是开关，是宪法；
4. **外部内容永不直接变记忆**：untrusted 标签贯穿 P3–P4；
5. **缓做项有明确触发条件**：没有触发条件的功能不进排期；
6. **工具与技能只在云端工具调用模型上启用，本地模型纯聊天**（2026-11-22 分流裁决，全项目硬约束，见 AGENTS.md「模型调用约束」）：本地路径零工具调用、零 skill 注入，不为其做任何工具协议 hack；
7. **能力不得重复实现，优先在 tool 中维护**（2026-11-22，见 AGENTS.md「能力与架构约束」）：任何能力只允许一份权威实现（载体是工具），路由/前端/skill 只消费工具输出，不得平行复写；
8. **一切以 AI 优先**：新能力的默认交付面是 AI（工具/对话），UI 只是能力的管理与展示面，不绕过 AI 自建路径。
