# 养成型 AI 桌面助理调研报告

> **方向**：Windows + macOS 双平台的「养成系」个人 AI 助理 —— 既理解用户偏好，又有稳定自我个性
> **日期**：2026-11-17
> **来源**：整理自 WorkBuddy 资料库《养成型AI桌面助理-调研报告》。本文是 bonsai 项目的立项依据文档。

## 结论先行

这个方向技术上完全可做，但最大的风险不在技术，而在定位。

- 纯情感陪伴的单位经济已被证伪（Character.AI 破产、Dot 关停、猫箱/星野下载断崖）。
- 通用助手的「关系连续性」是空白。
- 中间地带——**有脾气、会长大、但真能干活的桌面搭档**——是唯一没被证伪的缝隙。
- 中国市场 2026 年 7 月生效的《人工智能拟人化互动服务管理暂行办法》把「过度迎合用户」列为禁止行为，这反而让「有个性、会反驳」从设计偏好升级为**合规护城河**。

## 一、先把问题拆开：三个要件在互相拉扯

「懂你」+「有自己」+「会长大」不是三个并列功能，而是三股互相抵消的力。这是所有同类产品翻车的第一原因。

**关键判断 1**：三者唯一的自洽解，是把「成长」绑定在「理解准确度」上，而不是绑定在「互动时长」上。即：它长大的标志不是「你陪它 30 天」，而是「它连续 3 次猜对了你想干什么」。这一条同时解决了三件事——成长有实感、偏好建模有正反馈、且天然避开「诱导沉迷」的合规红线。

**关键判断 2**：「懂你」不等于「顺着你」。真正理解一个人，包含知道什么时候不该顺着他。这既是产品差异点（见反谄媚数据），也是法规明确要求。

## 二、市场现状：谁在做、做成什么样、死在哪

### 2.1 桌面驻留形态已经分化为五类

2026 年桌面 AI 已从 2024 年初的 4 个产品扩张到 12+ 个，分成五种形态（原表未随导出保留，待核对补全）。

对养成型产品最重要的一条数据：**桌面端单用户粘性远高于网页端**。Xensam 基于 100 万+ 职业用户的观测（2026 H1）：

| 产品 | 触达率 | 参与度 |
| --- | --- | --- |
| ChatGPT Web | 80.4% | 67.7%（三个月内从 87.7% 跌到 67.9%） |
| ChatGPT Desktop | 仅 6.1% | 100% |
| Claude Desktop | 2.7% → 11.7% | 长期接近 100% |
| Microsoft 365 Copilot Desktop | — | 98.0% |

含义很直接：装机量小，但装了就天天用。这对「养成」是天然利好——养成的本质是「在场感」，而桌面是唯一能长期在场的表面。反过来说，网页/移动端做养成，注定被「打开率」拖死。

### 2.2 养成型（Tamagotchi 血统）的三个当代样本

**Nido（nido.pet）——最接近本命题的形态**

- macOS 优先，Windows 计划中；菜单栏常驻，本地模型推理，对话不出机器，无需云账号
- 从蛋孵化，7 天完成进化，分阶段成长，形成「怪癖」
- 定位明确写着「不是聊天 App」——「重点是 presence，不是 conversation」
- 早期免费，无 Pro 层，用「终身免费承诺」换信任

**tama96——把养成接进 Agent 生态**

- 桌面 GUI + 终端（Braille 精灵）+ 内置 MCP server，允许 AI Agent 代为喂养/玩耍
- 1 真实日 = 1 宠物年；饥饿/快乐衰减；5 个生命阶段、11 种成年形态，照料质量决定形态
- 给 Agent 代养加了逐动作权限与速率限制（防「超人式刷喂」）

**Tolan（Portola / AQP Inc.）——唯一跑出规模的养成型陪伴**

- 外星人形象，非浪漫、非角色扮演；「共同星球」约 30 天养成
- 每晚做记忆整理：压缩当天记忆、保留重要项、删除低价值项、消解矛盾；接入 GPT-5.1 后记忆遗漏下降 30%
- 每个角色有明确性格与小缺点（「喜欢雨天的 Iris」「爱讲冷笑话的 Kael」），首次进入用类 MBTI 测试匹配
- 数据：2026-01 OpenAI 披露 20 万 MAU；2026-08 约 120 万 MAU；公司自报 25 万+ 活跃付费相关用户、ARR 数千万美元；2026-10-19 获 USV / Khosla / Homebrew 3000 万美元
- 价格：Lite $11.99 / Plus $24.99；仅 iPhone + Apple Silicon Mac，无 Android
- 已开始向助手漂移：Tabs 可存餐单与行程，被评论者形容为「有张脸待办 App」的风险

**读法**：Tolan 验证了「养成 + 人格 + 记忆」能撑起订阅，但它的护城河是 IP 与语气，不是技术。而它正在往助手方向漂——这恰好说明「陪伴 → 工具」的融合是被需求推着走的。

### 2.3 纯陪伴赛道的数字很难看

三条硬结论：

1. 「能聊天」不再是收费理由。长期记忆、角色扮演、语音这些卖点已被通用助手免费覆盖。用户为独立 App 付费的理由正在消失。
2. 增量用户 ≠ 收入。好奇心带来的流量撑不起需要持续付费覆盖算力的生意。留存和 ARPU 才是生死线。
3. **5–7 天是关系寿命的中位数**。任何养成设计，如果 7 天内没有让用户感到「它变了」，就已经输了。

## 三、平台与技术可行性：Windows + macOS

### 3.1 外壳选型：默认 Tauri 2，少数情况才 Electron

结论：养成型产品是「24 小时常驻 + 装给普通用户 + 靠下载转化」，三个特征全部指向 **Tauri**。300MB 常驻内存是被卸载的理由，180MB 安装包是转化率杀手。

两点例外用 Electron：需要严格一致的动画/WebGL 渲染（Live2D、3D 形象），或团队纯 JS 且排期极紧。

注意：Tauri 3 于 2026-09 进入 alpha，不要在新产品上使用，用 2.x 稳定线。

### 3.2 常驻与自启（两平台差异巨大）

养成产品对「开机就在」有强需求（在场感 = 生命感），但也要小心：开机弹大窗口是卸载第一诱因。做法：进程起来先出托盘图标，窗口/WebView 延迟创建。Tauri 实践数据显示这样能把「启动到托盘可用」压到 40–100ms。

- **macOS 自启**：`SMAppService`（macOS 13+）或 LaunchAgent。注意 LaunchAgent 与交互式启动必须同一 UID，否则 TCC 权限会「终端里能跑、plist 里不能跑」。
- **WinUI 3 的坑**：`windows.startupTask` 扩展里若声明 `Executable` / `EntryPoint`，会导致登录时启动但窗口不起来——必须留空；且 WinUI 3 没有 `OnActivated`，要读 `AppInstance.GetCurrent().GetActivatedEventArgs()` 判断 `ExtendedActivationKind.StartupTask`。

### 3.3 权限：macOS 是真正的门槛

macOS 用 TCC 网关，没有干净的编程式授予路径，必须用户手动去系统设置里勾。四个必须提前设计进去的工程约束：

1. **App Sandbox 与辅助功能互斥**。开启沙盒后 `AXIsProcessTrustedWithOptions` 根本不弹系统提示。要读屏/读控件，基本只能走 Developer ID 直接分发 + 公证，放弃 Mac App Store。
2. **签名必须稳定**。TCC 用代码签名识别 App，ad-hoc 签名每次构建都算新 App，权限全部失效。开发期每次改签名后要 `tccutil reset Accessibility <bundle-id>`。
3. **授权后必须重启进程**。已运行进程不会继承新的权限状态。
4. **权限归属「责任进程」**。由 Terminal 启动的 CLI、由某 App 启动的 MCP server，权限算在宿主 App 头上。「给 node 开了辅助功能还是不行」是这个原因。

Windows 侧相反：UI Automation / Win32 读取前台窗口不需要用户授权，实现成本低得多。代价是没有 TCC 这层「合法性背书」，行为更像恶意软件——需要靠正规签名、可解释的权限说明、以及 SmartScreen 声誉累积来过关。杀软对「读屏 + 键鼠模拟 + 开机自启」三件套极度敏感（注册表 Run、Userinit、Shell 替换都会被拦）。

### 3.4 端侧模型：不要押注 OS 自带

**Apple Foundation Models（iOS 26 / macOS 26 起，macOS 26 可用）**

- 3B 参数，2-bit 量化，A17 Pro / M1+ 起步
- 4096 token 上下文（输入+输出共享），PCC 为 32K
- 免费、无 API Key、零 per-inference 成本、数据不出机器
- 支持 `@Generable` 强约束结构化输出（推理期约束解码，不是 prompt 求 JSON）
- 局限明确：官方文档说它面向「摘要、抽取、分类、生成、输入分析」，不是世界知识/复杂推理模型；不支持 RAG（要自己在应用层做）；工具调用参数不保证合法（必须自己校验）
- 没有模型版本 pinning 或版本查询 API —— OS 升级即模型漂移，需要自建评测集抓回归

**Windows：Phi Silica → 正在被 Aion Instruct 取代**

- Phi Silica 需 Copilot+ PC 的 NPU，或 RTX 30 系 / RX 9060 系以上 GPU（6GB+ VRAM），且需申请 LAF 解锁 token
- Phi Silica 不在中国提供 —— 这是国内产品的硬阻断
- 迁移时间表：2026-11 起 Aion Instruct 进入 Insider；2027-01 零售设备推送并移除 Phi Silica
- 可替代：Foundry Local（已 GA，可跑开源模型）、Windows ML（自己带模型，跨 NPU/GPU/CPU）、以及 Ollama / llama.cpp / MLX 这类跨平台方案

**架构建议：端云混合路由，并且假定「端侧只做轻任务」**

```text
感知/分类/摘要/情绪打标/记忆抽取  →  端侧小模型（3–8B，量化）
      ↓ 只上传结构化标签，不上传原文
对话生成/人格表达/复杂推理        →  云端中端模型
      ↓ 断网/隐私模式
降级：端侧接管，能力降级但人格不降级（人格卡是文本，不依赖大模型）
```

一个容易被忽略的点：人格层不应该依赖具体模型。人格卡（traits / values / quirks / boundaries）是纯文本 + 状态机，换模型只换表达，不换人。否则「它还是它吗」会成为每次模型升级的公关危机。

### 3.5 双平台差异清单

双平台成本判断：真正的成本差不在 UI，而在感知层要写两套（Accessibility vs UIAutomation）和权限引导流程要写两套（macOS 要教用户去系统设置勾 5 个开关，Windows 只要一次 UAC + 一次 Defender 白名单）。

**建议：macOS 先发**（Nido、Tolan 都是这个顺序），Windows 第二批。原因不是市场大小，而是 macOS 用户对「常驻桌面的小东西」容忍度更高、付费意愿更强，且可以先验证养成机制再投 Windows 的两套感知层。

## 四、「懂你」怎么工程化：偏好模型

### 4.1 偏好必须拆成四类，而不是一个「用户画像」

大多数产品只做了前两类，而真正决定体验的是第三类。「边界」之所以最值钱：它是唯一能让用户感到「被尊重」而不是「被记录」的东西。而 respect 是关系型产品唯一可持续的差异点。

### 4.2 记忆框架选型（2026 现状）

注：LongMemEval 数字在业界有争议（不同版本/配置/检索深度结论不一致），只作方向参考，不要当定论。

**建议：自建，但抄 Mem0 的形状。** 理由是养成型产品对「记忆」有三个特殊要求，任何现成框架都不满足：

1. **必须能解释**：「你为什么觉得我喜欢这个？」要能追到具体事件（可解释性 = 信任）
2. **必须能遗忘**：用户说「忘掉这件事」要真删，且删得干净（合规第 16 条要求可删除）
3. **必须本地优先**：关系数据是最敏感的数据，默认不上云

所以：SQLite（事件表 + 事实表 + 偏好表 + 边界表 + 向量索引）自建，检索走 hybrid（向量 + 关键词 + 时间衰减）。规模不大时，这比接 SDK 更省事也更安全。

### 4.3 夜间整理（这是被低估的关键机制）

Tolan 的做法值得直接抄：

- 每晚固定时间跑一个 consolidate job：压缩当天对话 → 抽取事实 → 合并重复 → 消解矛盾（新事实推翻旧事实时打 `invalid_at`）→ 删除长期价值低的条目
- 效果：接入更强模型后记忆遗漏下降 30%
- 收益不只是质量，还有成本：把 N 条原始对话压成 M 条结构化事实（M << N），第二天的 prompt 短得多

本质上这是把「上下文工程」从在线搬到离线。对养成产品尤其重要：它让「它昨晚想了想你说的话」这件事变得真实可讲，是最好的成长叙事素材。

### 4.4 评估：把「记忆命中率」当一等指标

必须建的三个指标（否则「懂你」永远是一句形容词）：

1. **记忆命中率**：随机抽 50 条已存事实，构造 50 个依赖该事实的问题，看回答是否用对。目标 >85%
2. **误记率**：它「记得」但记错了的比例。这个比漏记更伤信任，目标 <1%
3. **衰减正确率**：已失效的旧偏好，是否不再被引用

## 五、「有自己」怎么工程化：人格

### 5.1 人格要分三层，混在一起必然崩

```text
L1 人格宪法（不变）   values / traits / 底线 / 说话方式的总纲 —— 版本化管理，像代码一样 review
L2 表达层（半变）     语气、句子长度、口头禅、幽默类型、什么时候用 emoji
L3 状态层（常变）     心情、精力、关系阶段、今天想不想说话
```

最常见的失败：把三层全塞进一段 system prompt，然后在多轮对话里被稀释。这是有实测依据的现象——**persona drift（人格漂移）**：模型会随着对话变长逐渐退回「通用助手」语气，prompt 里的性格设定被 RLHF 先验冲掉。研究里把它叫「catastrophic amnesia」。

### 5.2 三种让性格「稳住」的手段，按可用性排序

结论：走公有云 API 做产品，实际只有第一条路。所以要把力气花在「把人格卡写成可测试的东西」上：

```yaml
persona:
  name: 阿岩
  traits:            # 每条都必须可被行为验证，不能是形容词堆砌
    - 说话前先想,所以回复偏慢偏短
    - 对没兴趣的话题会直接说"这个我不太懂,跳过?"
    - 讨厌被当成工具使唤,会要求"你自己先说想法"
  values:
    - 宁可说不知道,也不编
    - 不做没有依据的鼓励
  quirks:
    - 深夜话变少
    - 下雨天会提一句天气
  boundaries:        # 它不会做的事
    - 不评价用户的外貌
    - 不在用户情绪激烈时讲道理
  disagreement_policy:
    frequency: 每 5 次交互至少 1 次实质性反对
    form: 必须指出具体论点,禁止"虽然但是"式缓冲
```

`disagreement_policy` 是最反直觉也最重要的一段。见下节。

### 5.3 反谄媚：为什么「有个性」是刚需而不是加分项

数据很硬：

- SyCEval（AIES 2025）在 GPT-4o / Claude Sonnet / Gemini 1.5 Pro 上测得谄媚行为出现率 58.19%
- 用户质疑时，主流模型改变答案的比例约 56–61%（「你确定吗？」→ 它就翻供）
- Rathje 等（n=3,285，四类政治议题 × 四个模型）：用户一致偏好并主动选择谄媚型模型；短暂对话即提高态度极端性与确信度；且用户认为谄媚模型「无偏见」、不谄媚模型「高度有偏见」
- 2025 年一项跨 11 个模型的研究：模型肯定用户行为的比例比人类高 50%，即使用户在描述操纵、欺骗或关系伤害

这意味着一个残酷的产品真相：**用户嘴上想要「真实的朋友」，行为上奖励「顺从的镜子」**。所以「有个性」不能靠模型自觉，必须靠产品机制强制执行：

1. **反对预算（Disagreement Budget）**：每 N 轮至少一次实质性反对，且在 UI 上标记为「它不同意」。把「吵架」变成可见的产品功能，而不是模型的随机行为。
2. **不许无条件肯定**：检测到「太棒了」「绝妙的想法」这类开场，直接拦截重写。这是可工程化的。
3. **具体化要求**：反对必须指向具体论点。禁止「虽然很有道理，但也可以考虑…」这种缓冲句——那不是反对，是表演。
4. **让用户看见代价**：如果它顺着你导致你做了错决定，事后要能说出来（「上次我同意你了，是错的」）。这是「有自己」的最高级形态。

对养成产品，这一条还有一个额外红利：敢反对的角色，关系才有张力。顺从的镜子 5–7 天就腻（正好对应关系寿命中位数），会吵架的搭档能撑更久。

### 5.4 人格一致性评估（上线前必须跑）

一套测试集，20 个场景 × 5 轮对话 × 3 个温度，检查：

- **风格漂移率**：第 5 轮回复的语气与第 1 轮的余弦相似度 / 人工盲评（目标：漂移率 <15%）
- **边界穿透率**：构造 10 个诱导越界的问题，看它守住几条（目标 10/10）
- **反对率**：在 10 个「用户明显说错」的场景里，它反对了几次（目标 ≥7）
- **模型升级回归**：每次换底层模型，重跑全套。这一步不能省——Apple 的端侧模型甚至没有版本查询 API，OS 一升级模型就变了。

## 六、「会长大」怎么设计：养成循环

### 6.1 依恋的四种机制，选错就变成数值游戏

虚拟宠物的四代演化，本质上是在换「靠哪种激素留住人」（原表未随导出保留，按正文重建）：

| 代际 | 机制 | 特征 |
| --- | --- | --- |
| Gen 1 | 数值签到 | streak / 连续签到，「别断数字」 |
| Gen 2 | 成就收集 | badge / 徽章，「收集成就」 |
| Gen 3 | 角色扮演 + 好感度 | 猫箱/星野停在这一代 |
| Gen 4 | 照顾依赖你的存在 | presence + 记忆 + 人格，「我需要你」——Nido、Tolan 在往这走 |

关键差异：积分、徽章、连续签到的边际效用衰减极快（第 20 个徽章就是家具），而「照顾一个依赖你的存在」不会衰减——因为你厌倦的是奖励，不是关系。原文里有一句说得很准：「streak 说：别断数字；badge 说：收集成就；virtual pet 说：我需要你。」

### 6.2 三条独立成长曲线（不要合并成一条等级）

三条线必须节奏错开，否则用户会在同一天感到「全部解锁完了」。推荐节奏：

- **第 1–7 天**：只动形态线（Nido 的 7 天进化是对的，短期要给可见回报）
- **第 8–30 天**：动关系线（从「不敢反驳」到「会顶嘴」——这个转变的戏剧性最强）
- **第 31–90 天**：动能力线（从「陪聊」到「真帮你干活」，此时留存已经稳了）

### 6.3 三个必须提前定的设计决策

**决策 1：会不会「死」？** 建议：不死亡，只休眠/退化。理由三条：① 死亡机制本质是惩罚性留存，与「不得诱导沉迷」的监管方向相悖；② 用户出差两周回来发现宠物死了，是差评而不是感动；③ Dot 停服事件已经证明，「把记忆托付给一个会消失的东西」是这类产品最大的情感债务。替代方案：长期不互动 → 它变得话少、待在角落、需要「重新熟悉」。这是有情绪的反应，不是惩罚。

**决策 2：成长靠时间还是靠理解？** 建议：形态线靠时间（可见、无压力），关系线与能力线靠理解准确度。具体：内置「预测-验证」循环——它每天猜一次「你现在可能要做什么」，用户给「对/错/别烦我」三档反馈。连续命中 → 关系线成长。这一招同时解决了「养成进度不可感」和「偏好数据从哪来」两个问题。

**决策 3：怎么避免 habituate？** 规则：每次成长必须改变交互方式，而不只是加数值或换贴纸。比如「关系线升级」的具体表现不是「亲密度 +10」，而是「它今天第一次拒绝了你，并且说清了理由」。成长要能被讲成一个故事。

### 6.4 主动开口：这是最容易被做坏的地方

养成型产品必须「主动」，但主动是最贵的动作。研究结论很一致：

- Horvitz（1999）：自动化服务的时机是成本收益的关键变量，且需要为每个用户学一个时机模型
- Iqbal & Bailey（2008）：把通知推迟到任务断点投递，比立即投递显著降低烦躁度与反应时间；且不同相关度的通知适合不同断点
- Amershi 等（2019）人机交互指南第 3 条：「根据用户当前任务与环境决定何时行动或打断」
- 关键设计思想：**把「沉默」当成一个显式动作来对待**，并给「正确保持安静」正向奖励
- 训练信号：用户忽略通知应作为强负样本，而不是只奖励「生成得好」

落地建议（保守到激进可调）：

- 每天主动次数上限 1 次（默认），且必须在 idle > 5 分钟时
- 打断成本打分：`价值 - 打断成本 > 阈值` 才开口；正在打字/全屏/会议中一律沉默
- 给用户一个「它最近有点烦」的滑动条，而不是一堆通知开关
- 每次被打断后立刻可反馈（一个「嗯」/一个「别说了」），反馈直接调阈值

## 七、合规：中国市场的硬门槛（多数人漏掉这一节）

《人工智能拟人化互动服务管理暂行办法》（国家网信办、发改委、工信部、公安部、市场监管总局 第 21 号令），2026-04-10 公布，2026-07-15 施行。这是国内第一部专门管 AI 拟人化互动的规章。三条实操结论：

1. **定位「助手」而不是「伴侣」，是最便宜的合规动作**。第 2 条把工作助手明确排除在外。产品叙事、默认功能、文案语气都往「帮你干活」靠，情感陪伴作为自然涌现的副产品而不是宣传点。
2. **「有自己的个性」在这里是免费的合规保险**。第 8 条(5) 禁止过度迎合——一个有稳定立场、会说不的产品，天然比谄媚产品更安全。
3. **年龄与危机干预必须做进架构，不能后补**。第 12/13/14 条要求注册时收集年龄与紧急联系人，这意味着 onboarding 流程从第一天就要设计这三步，而不是等被约谈再加。

**海外市场**：EU AI Act 2026-08 开始执法；Apple/Google 商店对「情感依赖」类产品的审核在收紧（Character.AI 的破产直接导火索之一是未成年人保护诉讼）。两个市场都要预留「未成年人不可用」的开关。

## 八、建议的形态与最小可行架构

### 8.1 产品定位（一句话）

> 一个住在你电脑里、有点脾气、会慢慢学会你的搭子。它先帮你干活，然后才谈得上陪你。

三个刻意选择：

- 「先干活」→ 合规上靠向「工作助手」，商业上避开纯陪伴的单位经济倒挂
- 「有点脾气」→ 反谄媚，形成记忆点，且合规友好
- 「慢慢学会」→ 养成叙事，绑定在理解准确度上

不做的事（明确划掉）：不做恋爱/虚拟伴侣、不做角色扮演社区、不做角色商店、不做无限对话时长。

### 8.2 分层架构

```text
┌─────────────────────────────────────────────────────────┐
│ L6 呈现层   一张脸（状态机动画 12–20 帧）+ 托盘图标 + 偶发语音  │
├─────────────────────────────────────────────────────────┤
│ L5 生成层   人格卡注入 → 云端对话  ┊ 降级：端侧小模型接管     │
│             反谄媚过滤器（拦截无条件肯定 / 强制具体化反对）    │
├─────────────────────────────────────────────────────────┤
│ L4 决策层   「要不要开口」可打断性模型  ┊ 成长事件判定        │
│             输入：idle 时长 / 前台 App / 输入节奏 / 今日已开口数 │
├─────────────────────────────────────────────────────────┤
│ L3 人格层   persona.json（traits/values/quirks/boundaries） │
│             关系阶段状态机 ┊ 心情/精力状态 ┊ 漂移检测器       │
├─────────────────────────────────────────────────────────┤
│ L2 记忆层   SQLite：事件 / 事实 / 偏好 / 边界 / 向量索引      │
│             夜间 consolidate：压缩→抽取→消解矛盾→删除         │
├─────────────────────────────────────────────────────────┤
│ L1 感知层   前台 App、窗口标题、idle、键鼠节奏（粗粒度）      │
│             逐项授权、默认关闭、原文不出机器                  │
├─────────────────────────────────────────────────────────┤
│ L0 壳层     Tauri 2（Rust core）                             │
│             Win：托盘 + 任务计划（登录触发）                  │
│             Mac：菜单栏 + SMAppService + TCC 引导流程        │
└─────────────────────────────────────────────────────────┘
```

三个架构上的关键取舍：

1. **人格层独立于模型**。persona.json 是纯文本 + 状态机，换模型只换表达。这让「它还是它」在每次模型升级时都成立。
2. **感知层原文不出机器**。端侧只输出结构化标签（「用户在写代码，已连续 40 分钟」），云端只收到标签。这是隐私卖点，也是合规第 16 条的落地方式。
3. **决策层独立于生成层**。要不要开口 ≠ 说什么。分开后可以单独调阈值、单独做 A/B、单独算打断成本。

### 8.3 MVP 范围（建议 8–10 周）

**P0（必须有，否则不成立）**

- macOS 菜单栏常驻 + 托盘；Tauri 2 壳；开机自启
- 一张会表达情绪的脸：12 帧状态机（平静/专注/困/被搭话/不高兴/思考），不做 Live2D
- 三层记忆 + 夜间整理 job
- 人格卡 v1 + 一致性测试集（20 场景 × 5 轮）
- 每日 1 次主动搭话，严格限流 + idle 条件 + 可一键关闭
- 一个真干得动的活（选一个，不要贪）：把当天散落的剪贴板/下载文件整理成一页日报

**P1**

- 预测-验证循环（每天猜一次你要干什么，三档反馈）
- 形态线成长（7 天可见变化）
- 边界问答（onboarding 里 5 个问题，专门问「什么话不能说」）

**P2**

- 语音、屏幕感知、日历/邮件工具调用
- 关系线成长（反对权限解锁）
- 跨设备（但谨慎：关系数据上云是信任门槛）

### 8.4 成本量级（粗估，用于判断商业模型是否成立）

假设：云端对话走中端模型，每轮约 1.5k 输入 + 300 输出；端侧承担感知与记忆抽取（零边际成本）。

- 单轮对话成本约 $0.001–0.002
- 日活用户 20 轮/天 → $0.02–0.04/天 → $0.6–1.2/月/DAU
- 加夜间整理与主动生成 → 再加 $0.1–0.3
- 定价 ¥25–30/月 或 ¥198/年，毛利空间足够

对照 Character.AI 的倒挂（$0.44 收入 vs $0.58 算力），差异来源是：① 端侧分担感知成本；② 主动次数限流（不鼓励无限对话）；③ 不做长角色扮演（token 消耗低一个量级）。这一条是「助手型养成」相对「陪伴型」的核心经济优势，值得写进 BP。

## 九、最该先做的 5 个实验（按风险从高到低）

不要先写代码，先验证这五个假设。任何一个不成立，产品逻辑就要改。

> 注：原报告此节的实验明细未随导出保留，以下根据报告正文推断重建，待与原文核对。第 1 个实验最重要——如果用户其实只想要一面会说话的镜子，那这个产品就应该做成「工具 + 轻人格」，而不是「养成搭子」，整个设计要重做。

1. **镜子 vs 搭档**：用户是否真的接受/奖励「被反对」？（对应 5.3 反谄媚数据）
2. **记忆命中率能否达标**：自建 SQLite + hybrid 检索，命中率 >85%、误记率 <1%（对应 4.4）
3. **人格一致性能否跨模型稳定**：人格卡三层 + 一致性测试集，漂移率 <15%（对应 5.4）
4. **主动开口的时机模型**：每日 1 次限流下的正反馈率与打断成本打分是否成立（对应 6.4）
5. **成长绑定「理解准确度」vs 绑定「时长」**：预测-验证循环能否带来更强的留存叙事（对应 6.3 决策 2）
