> **状态**：G1–G4 已实施（2026-11-19，110 单测全过）；S2「自述引用感知摘要」按 §3.7 降级为阶段自述
> **日期**：2026-11-19

## 1. 目标与非目标

### 目标

1. 让用户在 **7 天内至少 3 次感到「它变了」**（调研 §六：5–7 天是关系寿命的中位数，
   7 天内没有可见变化就已经输了）。
2. 形态线**靠时间推进、不靠数值**（§6.3 决策 2）：真实使用天数达标即成长，
   无压力、无签到、无任务清单——养成的回报是「看见它长大」，不是打卡。
3. 每次成长**改变一点交互方式**而不只是换贴纸（§6.3 决策 3）：每次升阶伴随
   一处新的可交互行为（poke 反应 / 自述文案 / 新表情），成长能被讲成一个故事。
4. 不死亡，只休眠（§6.3 决策 1）：长期不互动 → 落叶待机形态，回来即恢复；
   阶段永不倒退。

### 非目标（P1 明确不做）

- 不做关系线 / 能力线（P2，节奏按 8–30 天 / 31–90 天错开）。
- 不做 Live2D、不做骨骼动画、不扩帧数——形态仍是单张 SVG 分组 + CSS 过渡。
- 不做数值好感度 / 经验条 / 连续签到（调研 §6.1：Gen 1/2 机制边际效用衰减快）。
- **不把已有功能回退成「解锁项」**：记忆、主动搭话、预测、日报 P0 已上线，
  形态线只加东西、不扣东西（回退即负成长，伤信任）。
- 不主动弹窗播报成长——用户打开窗口时才看到（一天最多打扰一次的红线不破）。

## 3. 核心机制设计

### 3.1 四阶段 × 7 天节奏

```text
S0 破土   第 1–2 天   一颗芽，两片叶
S1 抽枝   第 3–4 天   长出侧枝，第三片叶，poke 有了新反应
S2 成形   第 5–6 天   现在的完整树形（当前默认形态恰好在 S2 出现）
S3 成景   第 7 天起   开花 + 盆面苔藓点景，解锁一个 transient 表情
```

节奏依据（调研 §6.2）：第 1–7 天只动形态线；四阶段保证 **2/4/6/7 天各有一次
可见跳变**，中间由「日微变化」填缝（见 3.3），7 天内共 ≥3 次可感变化。

设计不变式（代码强制）：

1. **阶段只进不退**：stage 单调递增，休眠降的只是「气色」不是「阶段」。
2. **形态由 Rust 决定**：Rust 算出 `(stage, dormant, day_index)` 推给前端；
   前端只做 SVG 分组显隐 + CSS 过渡——与 face 状态机同一铁律。
3. **推进可重放**：所有状态变化写 `growth_log`，解锁时刻可审计、可测试。
4. **微变化确定性**：日微变化由日期哈希播种，同一天重开窗口不长出不一样的叶
   （成长必须诚实，随机数机器不可信）。

### 3.2 Schema v4：`growth` 表（状态）+ `growth_log` 表（审计）

```sql
CREATE TABLE IF NOT EXISTS growth (
    id            INTEGER PRIMARY KEY CHECK (id = 1),  -- 单行状态
    born_at       TEXT NOT NULL,      -- 出生锚点（本地时间 RFC3339）
    stage         INTEGER NOT NULL DEFAULT 0,          -- 0..3
    last_tick_date TEXT,              -- 最近一次推进检查的本地日（幂等用）
    dormant_since TEXT                -- 进入休眠的时间；NULL = 气色正常
);

CREATE TABLE IF NOT EXISTS growth_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    stage       INTEGER NOT NULL,     -- 解锁到的阶段
    unlocked_at TEXT NOT NULL,
    notified_at TEXT,                 -- 打开窗口播报的时间；NULL = 待播报
    note        TEXT                  -- 播报措辞（人格模板渲染结果，存档）
);
```

- **出生锚点**：首启时写 `born_at = now`；若库里已有更早的 events，回填最早
  事件时间（老用户不重头再来）。锚点一次性写入、永不变更。
- **推进检查**：沿用 60s 轮询模式加一个低频支路——每次检查先比对
  `last_tick_date`，同一天不重复算（与 predictions 的 UNIQUE(date) 幂等同思路）。
- `forget_all` 级联清空两张表（合规第 16 条延伸）；`forget_session` 不动它们
  （成长是跨会话事实，不属于单会话记忆）。

### 3.3 日微变化（填缝，不是升级）

阶段之间每天也要「有点不一样」，否则 5、6 天用户会怀疑停更了：

- **叶色渐深**：`leaf` 填充色按 `day_index` 在两档色间插值（CSS 变量，
  前端按 Rust 给的 day_index 设置）；
- **新叶点缀**：每满 1 天加一片小叶（≤6 片封顶），位置从 4 个预设槽位按
  日期哈希挑选——确定性、可快照测试；
- **caption 自述**：按 `(stage, day_index, 时段)` 从模板池选一句，3 套语气
  模板按日轮换（复用 predict 的做法），阿盆的吐槽随阶段长大而变锋利。

### 3.4 休眠（决策 1 的落地：不死亡，只待机）

```text
近 7 天 events 无 activity（perception/chat/proactive 任一都没有）
   → dormant_since = now，外观切换落叶态（叶黄、嘴平线、头微垂）
   → caption：「好久没人理我了。」
用户一回来（任意 activity）
   → 清 dormant_since，外观当帧恢复，caption：「哦，你回来了。」
```

- 休眠是**外观与语气**状态，不锁任何功能、不扣任何数据；
- 阶段照常随天数推进（时间线不因休眠暂停——它没有「饿死」，只是闹脾气）；
- 判定走 Rust 侧日期比较（SQLite datetime 与 RFC3339 混比的老坑不重踩）。

### 3.5 升阶播报：借通道、不占额度

升阶**不主动弹窗**。播报挂载在「用户打开主窗口」这个天然断点：

```text
growth_log 里存在 notified_at IS NULL 的行
   → 前端 show_window 时调 growth_status 命令
   → 返回 { stage, day_index, dormant, pending: [note...] }
   → 聊天流插入一条阿盆式播报气泡（S1:「抽了根新枝，别乱碰。」）
   → face_preview(Greeted) 短暂亮一下 + caption 换成新阶段自述
   → 写 notified_at（幂等，下次打开不再重复）
```

- 播报不写 proactive 事件、不占每日 1 次打扰额度——它是**用户主动来时**的
  回应，不是打断（与 §6.4 红线一致）；
- 措辞走 persona 渲染 + 固定模板池（每阶段 3 套，按 unlock 日轮换）；
  阶段自述逐阶段换锋利度，给「它性格也在长」的错觉。

### 3.6 前端形态分组（SVG 改造量可控）

`ui/index.html` 的脸改为按 `data-stage` 分组：

```html
<svg viewBox="0 0 200 200" data-stage="2" data-dormant="false">
  <g class="stage stage-0">…芽…</g>      <!-- 恒显 -->
  <g class="stage stage-1">…侧枝+第三叶…</g>   <!-- stage>=1 显示 -->
  <g class="stage stage-2">…当前完整树形…</g>  <!-- 即现有 pot/trunk/leafs -->
  <g class="stage stage-3">…花+苔藓…</g>
  <g class="dormant-overlay">…黄叶/平嘴…</g>   <!-- dormant 时覆盖 -->
</svg>
```

- 现有 SVG 原样收进 `stage-2` 组——**S2 形态 = 现在的样子**，用户已见的
  形状不突变，只向前长；
- 阶段切换用 CSS transition（scale/opacity 0.6s），不做逐帧动画；
- 预览页加「形态」演示位（复用表情页的 preview 模式，展示全部 4 阶段 +
  休眠态，方便验收与截图）。

### 3.7 每阶段一处交互变化（决策 3 的落地）

| 阶段 | 除外观外的交互变化 |
| --- | --- |
| S0 破土 | poke 只有 ripple（现状） |
| S1 抽枝 | poke 反应文案换新（模板池升级）；caption 开始有「它自己的状态」自述 |
| S2 成形 | 自述变得更具体（引用当天感知摘要里的一条，如「今天你开了 3 小时编辑器」——只复用已有数据，不新增采集） |
| S3 成景 | 解锁一个 transient 表情（得意，复用 face_preview 通道）；poke 会有概率晒盆景 |

> 若 S2「引用感知摘要」工作量超预期，降级为「自述带时段语气」，P1 不为此阻塞。

## 4. 数据流总览

```text
60s 轮询（growth 支路，低频幂等）
   │  本地日变化？→ 算 day_index = born_at 起的自然日数
   ▼
stage 达标且未解锁 → 写 growth + growth_log（待播报）+ add_event("growth_stage")
   │
   ├→ 前端 growth:stage 事件（若窗口开着，即时换形态）
   └→ 窗口关着 → 留在 pending，下次 show_window 播报（3.5）
休眠判定（每 tick）
   → 7 天无 activity → dormant_on；任意 activity → dormant_off
   → 两者都发 growth:stage 事件（前端换气色）
```

指标（常驻 CI 测试，纯函数即可测）：

- **升阶准时率**：解锁时刻 − born_at 的偏差 = 0（时间线必须诚实）；
- **播报幂等率**：同一 log 行 notified_at 只写一次（必失败反例：连开两次窗口）；
- **休眠正确率**：7 天无 activity 必进休眠、回来当天必恢复（含跨时区/跨日边界）。

## 6. 开放问题（待评审）

1. **阶段数取 4 还是 7**？4 阶段跳变明显、实现省；7 阶段更密但第 5–7 天会
   挤在一起。建议 4 阶段 + 日微变化填缝（本方案默认）。
2. **休眠阈值 7 天是否合适**？调研建议「长期不互动」但不给数。7 天 ≈ 一个
   假期长度；先固定 7 天不做设置项，观察回归行为再调。
3. **出生锚点回填是否公平**：老用户（已有历史 events）直接按最早事件日起算，
   可能一进来看就是 S2。备选：一律从本次升级起算。建议回填——「它其实已经
   陪了你 N 天」是更强的第一印象。
4. **S3 解锁的 transient 表情**（得意）是否与现有 6 态冲突？建议新增第 7 态
   `proud`，仅此一处、不进常规轮换。

## 7. 合规与隐私对照

- 形态判定只用本机已有数据（events 时间戳），不新增任何采集；
- 自述引用感知摘要时只出结构化标签（沿用 L1「原文不出机器」）；
- 不签到、不连续时长、不惩罚性数值——符合「不得诱导沉迷」的监管方向；
- `forget_all` 级联清空 growth / growth_log；休眠是情绪表达而非惩罚机制。
